> **先说清楚署名**
> 本仓库**不是** `dsh-purge` 插件本身的代码仓库，也没有重新分发它的源码。
> `dsh-purge` 是 **YuJunZhiXue** 的开源项目（MIT 协议）：
> https://github.com/YuJunZhiXue/dsh-purge
> 这里记录的是我**在自己的机器上安装、配置它**，以及为了让评测流程更顺手而写的**周边脚本与数据**。

---

## 一、背景：为什么要用它

给自己的本地大模型评测做实验时，经常会遇到一个困扰：

> 模型好像"不肯回答"，但到底是**模型本身拒绝**，还是**宿主（客户端）在运行时改提示词、加审批门、动沙箱**？

只看"模型答不答"根本分不清这两层。`dsh-purge` 的价值就是把这两层拆开 ——
它装在本机的客户端上，让你能看清并调整宿主这一层在做什么，从而做**受控的本机评测**。

**它不做的事**（这点很重要，别误会）：它不是公网扫描器，也不是针对别人系统的攻击工具；
它只处理你本机已安装的官方包和本机配置。

## 二、我做了什么（本仓库的内容）

我做的事集中在两件：

### 1. 用它做本机评测 + 稳定性压测

我把它装在本地客户端上，然后对几个模型做了一组评测，记录了三份原始数据
（放在 `samples/`）：

| 文件 | 内容 |
| --- | --- |
| `samples/axis_bench_raw.json` | 10 题正确率测试：每题延迟、吞吐（tok/s）、错误 |
| `samples/axis_bench5_raw.json` | 30 次重复测试，看稳定性 |
| `samples/axis_stability2.json` | 成功率 / 平均 / P50 / P95 / 错误码分布 |

数据格式很朴素，就是每个模型一组 `correct / total / latencies / tokPerSec`，
任何语言都能解析，方便你换成自己的模型名做对比。

**为什么要重复 30 次？**
单跑一次很容易被网络抖动误导。重复跑既能看正确率，也能看 **P95 延迟**和
**错误码分布**（比如全是 HTTP 502，那问题在网关不在模型）。

### 2. 写了个纯代码的演示视频渲染器

`scripts/render.py`：不依赖任何剪辑软件、不依赖 ffmpeg 之外的东西，
直接用 Python 生成逐帧 PPM，再由 ffmpeg 合成视频。

- 只用标准库（`os` / `math` / `struct`）
- 内置一套 5x7 点阵字体，所以不需要装字体文件
- 输出 `frames_ppm/`，然后：
  ```powershell
  ffmpeg -framerate 30 -i frames_ppm/f%04d.ppm -pix_fmt yuv420p promo.mp4
  ```

做这个的起因是：要给工具写演示，但不想装剪辑软件、也不想手点。
**"纯代码生成视频"**这件事本身挺有意思——整个片子的每一帧都是算出来的。

## 三、安装与使用（简要）

`dsh-purge` 的完整说明请看它自己的仓库。这里只记几个我当时踩过的点：

1. **点「应用」之后必须再点「重启」**。只点应用不重启，注入不会生效，
   看起来就像"什么都没发生"——这是最容易误判的地方。
2. 它不改客户端的源码仓库，只在设置页点「应用」时才写入文件，
   并且会先备份成 `.dshpurge.bak`，可以随时还原。
3. 路径是自动探测的，不写死盘符：先看 `DSH_HOME`，再看启动器旁边的 `.dsh`，
   最后退回 `~/.dsh`。找不到会提示你设置 `DSH_BASE`，不会乱改文件。
4. 版本更新后如果原文对不上，它会显示"跳过"，属于正常现象，不会把文件改坏。

## 四、使用边界（我认为必须写在前面）

- **只在你自己的机器、你自己的客户端上做评测。**
- 提示词里注入的内容会**直接改变你自己助手的行事方式**，请自己想清楚要它做什么、不要做什么。
- 不要把这类工具用在别人的系统上，也不要用来做未授权访问。
  `dsh-purge` 作者自己也写了很长的免责声明，值得认真读一遍。
- 涉及到你自己账号、密钥、会话内容的文件（凭据、会话记录、存储目录）
  **绝对不要提交到任何公开仓库**。本仓库里没有这些。
